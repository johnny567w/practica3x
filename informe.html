Detección de bordes Sobel con hilos en Java

Cálculo Paralelo · Práctica 3

1. Descomposición

Se divide la imagen, no el algoritmo. La imagen (Muttbach.jpg, 14306 × 8382 píxeles) se corta en franjas horizontales del mismo alto, tantas como hilos haya. Con 16 hilos: 8382 / 16 ≈ 524 filas por franja.

Las franjas se pueden procesar a la vez porque cada píxel de salida depende solo de sus 8 vecinos en la imagen en grises. En el borde de una franja basta leer una fila de la vecina, sin modificarla.

int bloque = (h + n - 1) / n;                         // 524 filas por franja
int y0 = k * bloque, y1 = Math.min(h, y0 + bloque);   // filas de la franja k

2. Asignación

Los hilos disponibles se obtienen con Runtime.getRuntime().availableProcessors(), que devuelve 16: un Ryzen 7 5800HS con 8 núcleos y 16 hilos. A cada hilo se le asigna una franja: el hilo 0 hace las filas 0–523, el hilo 1 las 524–1047, y así hasta el hilo 15.

t[k] = new Thread(() -> sobel(y0, y1));   // el hilo k procesa su franja
t[k].start();

3. Aglomeración

En vez de 120 millones de tareas pequeñas se hacen 16 bloques grandes de filas seguidas. Todos los hilos leen la misma imagen en grises, que nadie modifica, y cada uno escribe solo en sus filas del arreglo de salida. Así no hacen falta candados. Para unir el resultado basta con join(): cuando terminan los 16 hilos, la imagen ya está completa en un solo arreglo.

4. Mapeo

Cada hilo de Java es un hilo del sistema, y Windows lo coloca en uno de los 16 procesadores lógicos. Tiempos del filtro (mediana de 7 ejecuciones):

5. Ejecución

El código usa el patrón Modelo-Vista-Controlador:

  • modelo/ModeloSobel.java: carga la imagen, aplica el filtro con hilos y guarda el resultado.
  • vista/VistaConsola.java: muestra los datos y los tiempos en consola.
  • controlador/ControladorSobel.java: obtiene los hilos disponibles y coordina el modelo y la vista.
  • Main.java: arranca el programa.
javac Main.java
java -Xmx6g Main

Las imágenes generadas con 16 hilos y con 1 hilo son idénticas byte a byte.

Conclusión

Con 16 hilos el filtro es 8 veces más rápido. No llega a 16× porque solo hay 8 núcleos físicos y todos comparten la memoria.
